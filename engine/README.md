# engine: Google Research Football match engine

`sim.py` runs a full 11v11 GRF match (gfootball 2.10.2, Apache-2.0) with every player on GRF's builtin AI. It writes `../data/<name>.json` in the `../data/FORMAT.md` format and can fork a "what if" from any moment.

## Setup (no sudo, no docker; tested on this box)

```bash
T=/srv/neuland/workspaces/neuland/pl-hackathon/.tools   # anything writable; $HOME is read-only here
mkdir -p $T/bin $T/home && cd $T
curl -Ls https://micro.mamba.pm/api/micromamba/linux-64/latest -o mm.tar.bz2
tar -xjOf mm.tar.bz2 bin/micromamba > bin/micromamba && chmod +x bin/micromamba   # plain `tar -x` fails in this sandbox
export MAMBA_ROOT_PREFIX=$T/mamba XDG_CACHE_HOME=$T/cache CONDA_PKGS_DIRS=$T/pkgs HOME=$T/home
./bin/micromamba create -y -p $T/env -c conda-forge python=3.9 cmake make pkg-config cxx-compiler c-compiler \
  boost=1.82 sdl2 sdl2_image sdl2_ttf sdl2_gfx libgl-devel libglu mesalib libegl-devel libglvnd-devel psutil

E=$T/env; export PATH=$E/bin:$PATH CMAKE_PREFIX_PATH=$E CMAKE_POLICY_VERSION_MINIMUM=3.5 PKG_CONFIG_PATH=$E/lib/pkgconfig
pip download --no-deps --no-binary :all: gfootball==2.10.2 -d src
python -c "import tarfile; tarfile.open('src/gfootball-2.10.2.tar.gz').extractall('src')"
cd src/gfootball-2.10.2/third_party/gfootball_engine
cmake . -DPython_ROOT_DIR=$E -DPython_FIND_STRATEGY=LOCATION -DBoost_NO_SYSTEM_PATHS=ON -DBOOST_ROOT=$E \
  -DEGL_opengl_LIBRARY=$E/lib/libOpenGL.so.0          # conda only ships libOpenGL.so.0
make -j4                                               # takes about 10 min
mkdir -p lib && cp libgame.so lib/prebuilt_gameplayfootball.so && cd ../..
GFOOTBALL_USE_PREBUILT_SO=1 pip install .              # reuses our .so; setup.py's own cmake call lacks our flags
pip install six 'numpy<2'                              # six is a missing dependency; gym 0.26 needs numpy<2
```

## Run

Use `PY=$T/env/bin/python` with `HOME=$T/home`.

```bash
$PY sim.py --seed 42 --steps 3000 --out ../data/match.json        # about 20 s; also writes match.json.ckpt
$PY sim.py --fork ../data/match.json --at 66.5 --tweak step_up --player a6 --out ../data/fork-step_up.json
$PY server.py 8765   # GET /match/<name>, POST /fork {"match","at","tweak","params":{"player","secs","kind","len"}}
```

Tweaks control one player for `secs` (default 5), then hand him back to the AI. `--player` defaults to a sensible choice for the situation.
- `hold_line`: the defender keeps his depth and only shuffles sideways.
- `step_up`: the defender pushes up toward halfway.
- `sprint`: the player sprints at the opponent's goal.
- `pass_early` (`--kind short|long|high`): the ball owner turns toward goal and passes at once.
- `shoot`: the ball owner turns toward goal and shoots at once.

## Quirks
- **Determinism:** the match is a pure function of the seed. Two runs of seed 42 produced byte-identical JSON. A fork from a checkpoint matches a fork replayed from kick-off frame for frame, and `fork()` asserts that the fork frame equals the base frame. The `.ckpt` bytes themselves differ between runs, which does not matter.
- **Butterfly effect:** GRF uses one global RNG for all AI decisions. After a tweak, every later AI dice roll shifts, so a fork usually diverges completely within 2–4 s (ball distance from the base run: 0 m at +1 s, then 5–45 m from +2–4 s on). The cause is still only the tweak, but the rest of the match is "a different match". The interesting window is the first ~10 s.
- **Model:** all 22 players are external agents that send `builtin_ai`, so a fork can take over exactly one player without changing the config. Agent i controls player i. GRF directions are absolute (`right` = +x for both teams).
- **Time:** 3000 steps = 300 s of match time at 10 fps (GRF compresses a full match into this). Teams never swap ends: home = GRF left team, attacking +x. The difficulty is 0.8 for both teams.
- **Frames:** GRF skips frames while the ball is out of play, so after a goal the next frame is already the kick-off restart. The `kickoff` mode is rarely seen.
- **Events:** events are frame heuristics, documented in `detect_events`. First-time shots never register ball ownership, so shots are detected from the ball's kinematics.
- **Extra keys:** `meta.engine` (seed, steps) and `meta.forkOf.params` are additions to the format. The `.ckpt` files (pickled `get_state`, ~6.7 MB) are gitignored and regenerated by the base run. Without one, a fork replays from kick-off (≤ 20 s).
